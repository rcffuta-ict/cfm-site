What's built ICT

Four things: the Oracle raffle draw, plus trivia, bingo and the buzzer.

Oracle draw

Runs entirely on the venue laptop — no internet in the draw path. Includes a waiting room that stops the same number surfacing repeatedly.

Trivia

One question per round. Start → Lock → Reveal → Next, with faster correct answers scoring more.

Bingo

Everyone gets a shuffled card from one shared list. The host calls items; players mark their own squares and claim a line.

Buzzer

First finger wins. The order is decided inside the database, so two simultaneous presses get 1st and 2nd — never a tie.

All three games share one leaderboard and one /play screen, which switches itself to whatever the host has running. Members never pick a game.

Preview vs production

Any preview build shows a loud striped banner across the top of every page saying Preview build, with the branch name. Production shows nothing.

If you can see that banner, you are not on the app members are using. Check for it before the programme starts.

Laptop setup ICT

Do this before the hall fills up, while you still have good internet.

  1. Run the database migrations

    Once per Supabase project, in the SQL editor, in this order:

    docs/games-schema.sql     # sessions, rounds, trivia
docs/bingo-schema.sql     # cards, calls, marks, wins
docs/buzzer-schema.sql    # prompts, presses, buzzer_press()

    All three are safe to re-run.

  2. Set the environment

    On the laptop only, alongside the usual Supabase variables:

    ORACLE_LOCAL=1
    Skip this and the admin cannot log in on the laptop. A production build marks the session cookie secure, and browsers silently discard secure cookies on a plain-HTTP address like http://192.168.1.20:3000. Login appears to succeed, then nothing happens. It never reproduces on localhost, which browsers treat as secure — so it only shows up when you test from a second device. Never set this on the cloud deployment.

  3. Build and start, bound to the network

    pnpm build
pnpm start -H 0.0.0.0 -p 3000

  4. Find the laptop's address

    hostname -I        # e.g. 192.168.1.20

  5. Log in from the admin's phone

    Open http://<laptop-ip>:3000/admin on the actual phone that will run the draw. Doing this from a second device — not the laptop — is the only way to confirm the cookie fix works.

  6. Sync members

    On the Oracle console, press Refresh members. This is the one moment the Oracle talks to Supabase.

  7. Open the TV screens, then turn on sound

    http://<laptop-ip>:3000/oracle full-screen, plus the public /games in a second tab. On /games, click Tap anywhere to turn on sound — see below.

Sound ICT

The TV drives the room through the church PA. Phones stay quiet and tactile.

The TV needs one click before it will make any sound. Browsers refuse to start audio until someone interacts with the page, and nobody touches a TV once it's set up. /games covers itself with a full-screen Tap anywhere to turn on sound prompt until you deal with it. Do this while setting up, and check the level on the sound desk at the same time — not at 5pm with a full hall.

Adding the sound files

The game ships with simple synthesised tones so it is never silent, but real recordings are what make it feel like a game show. Drop files into public/sounds/ using the names below and they take over automatically on the next load — no code change, and you can add them one at a time.

You don't need all sixteen. Cues without a file of their own borrow a neighbour's — login-success uses locked-in, login-error uses lock, join uses reveal, and oracle-reveal uses winner. Anything with no file and no neighbour falls back to a synthesised tone, so nothing is ever silent. A real file always wins.
Any of .mp3, .wav, .ogg or .m4a works — use whatever you found, no conversion needed. Only the name has to match: buzzed.wav and buzzed are equally valid. MP3 is smaller, which matters if you're loading all sixteen over the venue's connection.
FilePlays onWhen
buzzedTV + phoneSomeone hits the buzzer. The classic quiz BZZZT — the most important file of the set.
buzzer-openTVHost opens the buzzer. A start gun.
round-startTVA trivia question appears.
tick / tick-urgentTVThe last 10 seconds, then the last 5.
lockTVAnswers close.
revealTVCorrect answer shown.
callTVA bingo item is called.
bingo-winTV + phoneSomeone gets bingo.
winnerTVFinal standings.
tap / locked-inPhoneA tap, and an accepted answer.
spinOracle TVLoops while the reels turn. Must loop seamlessly — trim it to whole reel clicks with no silence at either end.
spin-landOracle TVThe reels stop and the number lands.
oracle-revealOracle TVThe winner's name appears.
login-success / login-error / joinPhoneSigning in, failing to, and joining the game.
Trim the silence off the front of every file, especially buzzed. Leading silence becomes audible lag.
Sound never delays anything real. A tap sends its request before any sound or vibration starts, and audio failures are swallowed — so a missing file, a muted phone, or a browser that refuses to play can never cost someone a buzzer place or a speed bonus.

Free, no-attribution sources: Pixabay, Mixkit, or Freesound filtered to CC0. Search for quiz buzzer, game show correct, countdown tick, bingo bell.

The Oracle screen has its own sound gate. It's a separate page on a separate address, so turning on sound at /games does nothing for /oracle. Do both while setting up.

Where the files live

public/sounds/ in the repo. They're served as ordinary static files, but where they sit doesn't affect playback speed: every cue is fetched and decoded into memory the moment you turn on sound, so playing one is a memory read, not a disk or network fetch. That's why turning on sound during setup — not at 5pm — matters.

Keep an eye on total size. WAV files are large (a few MB each); the whole folder is downloaded once when sound is enabled. MP3 at ~128kbps is a fraction of the size for no audible loss on a PA.

On phones

Members get small confirmation sounds and haptics, at half volume, with a mute button in the corner of the play screen. They deliberately do not get the round-transition fanfare — 500 phones playing it would fight the PA rather than support it.

Setting up the games HOST

All from /admin/games. The page is four tabs.

Control·Trivia· Bingo·Buzzer

If no session exists yet, the Trivia tab offers Create session. One live session per event — creating a new one ends any previous, which is also how you clear rehearsal scores off the leaderboard.

Trivia questions

Add a question, fill two to six options, tap the circle beside the correct one. Arrows on the left reorder the run of show.

ActionAllowed whenWhat happens
EditNobody has answered yet, and it isn't on screenChanges wording, options, correct answer, points, timer.
DisableAny time except while on screenStays in the list but is skipped, and can't be started by mistake.
DeleteAny time except while on screenRemoves it and any answers given — those points leave the leaderboard.
Once someone answers, editing is locked. Changing the correct option after people have been scored would silently invalidate their points. Disable it instead.

Bingo list

One item per line. Choose the card size (3×3 to 5×5), whether the centre square is free, and whether winning needs any line or a full house. A 5×5 card with a free centre needs 24 items minimum.

The list locks once cards are handed out. Cards store positions in the list, so editing it afterwards would change what's printed on cards already in play. Use Reset to start over.

Buzzer prompts

One prompt per line. Set how many places score and the points for first. Prompts already buzzed on are kept when you save; the rest are replaced.

Running the Oracle HOST

From /admin on the laptop's LAN address.

Pick filters→Roll the Oracle→ Reveal→Reset

The waiting room

Every drawn number sits out the next few draws. Default is 3; set it to 0 to turn cooldown off. The queue lives on the laptop, so refreshing the console, switching phones, or restarting the server doesn't reset it.

If the pool is smaller than the cooldown — say four 500L sisters with three slots — the Oracle relaxes the cooldown one step at a time rather than giving up. It will never repeat the person who just went.

Keeping the snapshot fresh

People keep registering at the door. The console shows how many members are loaded and how long ago they synced, and warns once it's older than about ten minutes. Re-sync and clear the waiting room before the real programme.

Running trivia HOST

Control tab. Four buttons, once per question.

Start→Lock→ Reveal→Next
  • Start — puts the question on the TV and opens answers.
  • Lock — closes answers early; it locks itself at zero.
  • Reveal — shows the correct option, with the leaderboard.
  • Next — moves on, skipping disabled questions.

End session stops everything for the whole room. Confirmed first, because playing again means creating a new session.

Running bingo HOST

Bingo tab. Open-ended — no timer — until people start winning.

  • Start bingo — hands everyone a card. Cards are generated once and kept, so refreshing a phone never reshuffles one.
  • Call next — picks at random from what's left, or tap a specific item if you're reading from paper.
  • Undo last — for a misread. This also removes the marks players made against that item, so nobody keeps phantom progress.
  • Reset — clears every card, mark, call and win.
Players cannot mark ahead. The server refuses any square whose item hasn't been called, so a claim only has to prove the marks form a line.

Helpers

By default, phones show only the card — players must listen to the caller and watch the big screen. Setting GAME_HELPERS=1 turns on assistance: called squares get tinted, and phones list what's already been announced.

Helpers make bingo markedly easier and pull attention off the caller. Useful for a rehearsal or a gentler room; leave them off for the real thing.

Running the buzzer HOST

Buzzer tab. Read the prompt aloud, then open it.

  • Open buzzer — starts the race. This is the instant every reaction time is measured from, and nothing can be pressed before it.
  • Close — stops further presses without clearing the result.
  • Next / Previous — the new prompt stays shut until you open it deliberately, so nobody buzzes on a question you haven't read out.
  • Clear this prompt's presses — re-run the same prompt cleanly.
Ties are impossible. Position is allocated by the database inside a single statement, so two people pressing in the same millisecond get 1st and 2nd. Nothing depends on phone clocks — only on when the press actually reached the server. Tested at 60 simultaneous presses: 60 distinct places, no gaps.

The TV shows first place across the full width, with runners-up in a grid — a TV can't be scrolled, so places have to fit sideways.

Playing along MEMBER

What to tell the hall.

  1. Open the app and find Games

    The dashboard has a Games section listing what's on tonight, with anything running marked Live.

  2. Enter your Oracle ID

    The same number on your dashboard. It only accepts your number, so there's nothing to share or guess. Once you're in, you stay in — refreshing, locking the phone, or switching device all bring you back.

  3. Play whatever's running

    One screen handles all three games and switches itself.

    • Trivia — tap an option; it locks in immediately. One answer per question, and faster correct answers score more.
    • Bingo — tap squares as they're called. A square that hasn't been called won't mark. Hit BINGO! on a line.
    • Buzzer — hit the big button the moment it turns on. You'll see your place and reaction time straight away.
On patchy data a tap confirms straight away and settles in the background. If a submission genuinely fails, a tap to retry button appears — the answer isn't silently lost.

Network trouble MEMBER

The single biggest thing that made the beta feel unfair.

Someone on a weak signal loses a buzzer race and assumes they were slow. They have no way of knowing the network was the problem. So the app now tells them.

  • A warning appears by itself when a phone's connection goes bad for a sustained stretch — measured from the polling the app is already doing, so it costs nothing extra. It fires once, waits 90 seconds before repeating, and says "Connection's back" on recovery.
  • /network is a connection check anyone can run, linked from the dashboard. It reports round-trip time and lost requests with plain advice.
Round tripVerdictWhat it means
Under 300msStrongCompetitive on every game, buzzer included.
300–800msWorkableFine for trivia and bingo; a real handicap on the buzzer.
Over 800msWeakAnswers may land late or get lost.
That asymmetry is real. The buzzer is decided by the order presses reach the server, so latency is a direct handicap. Trivia's speed bonus decays gently over the whole round, so a few hundred milliseconds costs a point or two, not the answer. If the venue's network is poor, lean on trivia and bingo.

Advice worth repeating from the front: move away from the middle of the crowd, try switching between wifi and mobile data, or toggle flight mode to grab a fresh signal.

How scoring works HOST

One leaderboard, split by game.

Trivia

Base + speed

100 by default, plus up to 50 more — full at the start, zero at the buzzer. Wrong answers score nothing.

Bingo

Place-based

300 for the first line, then progressively less, floored at 20% so late winners still count.

Buzzer

Fastest fingers

200 for first, half for second, a third for third. Past the scoring places a press counts but earns nothing.

The TV board shows each person's split — T for trivia, B for bingo, Z for buzzer — alongside the total it's sorted by. Only people who have actually scored are listed; a board padded with zeros reads as broken on a big screen.

Every score is calculated on the server from the database's own record of when a round opened. Nothing a phone reports can change it.

The pre-flight, in order

  1. Log in from the admin's phone over the venue wifi

    Using the laptop's IP. Catches the cookie failure that nothing else catches.

  2. Turn on TV sound and set the desk level

    Before the hall fills up.

  3. Roll the Oracle with the internet unplugged

    Proves the draw is genuinely local.

  4. Create a fresh session

    Clears rehearsal scores. Then re-sync members and clear the waiting room.
